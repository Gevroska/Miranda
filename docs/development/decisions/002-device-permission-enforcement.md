# ADR-002: serialize device authority with session and input effects

- Status: accepted; implementation independently reviewed and locally validated; hosted validation pending
- Date: 2026-10-23
- Relevant requirement IDs: A01-A04, DEC-21, DEC-22, DEC-44, DEC-45; T07/T08/T17

## Context

[ADR-001](001-connection-bound-identity.md) binds HTTPS requests to their original pairing, but a dispatch snapshot cannot revoke a launch already retained by an RTSP socket or input already queued for a worker. The existing host has one RTSP owner and one input worker. Retaining a whole input connection across reconnects also retains its queue and held state, which lets old cleanup affect its successor.

Credentials and paired devices normally share one JSON file. Independent read/modify/write operations can lose a successful password or permission update. A replacement file must be secured before writing credentials or certificates and preserve the original file's access restrictions.

## Decision

Persist an explicit validated permission mask separately from the enabled gate. Every new pairing, including the first device, starts at zero. Missing or invalid stored masks mean zero. Preserve the pinned Apollo permission values and its List/View/Launch inclusion hierarchy; advertise only the implemented five input categories and three application actions. The authenticated, CSRF-protected administration endpoint updates either field without supplying a default for an omitted field.

Serialize durable pairing mutations through publication and reconciliation. Save the candidate before publishing it; retain prior in-memory authority on failure. Release the authorization mutex before awaiting session or input cleanup. Reconcile on the existing RTSP `io_context`, where launch preparation reserves the single pending slot before effects. A shared launch token carries its original pairing revision, readiness, cancellation and one-admission state. Recheck it at socket dispatch and immediately before ANNOUNCE allocation. Control-thread reservation cleanup posts without waiting, because RTSP cleanup may join that thread. Publish the shutdown fence before scheduling owner cleanup so a racing operation completes or rejects instead of waiting on an abandoned future.

Effective View permits joining the selected application. A different application while consumers remain is busy. A join does not execute the application or configure its active display. Launch permits an explicit Stop for everyone, as required by DEC-45. Individual revocation or disconnect preserves other principals and does not terminate the application solely because the departing client originated it.

Each connection receives fresh input state and explicit current grants. Validate and classify packets before admission, stamp independent category generations, and check them again at dispatch. Batching stops at a category or generation boundary so intervening modifier packets retain their order. Close revoked gates, advance their generations and await isolated cleanup on the existing worker before acknowledging the mutation. Delayed repeat, mouse, controller-back and initial mouse movement carry the same generation checks. Record each connection's actual mapped key and mouse contributions; first-owner press and last-owner release preserve another connection's held input, including synthetic modifiers and all five mouse buttons. Contribution identity ignores fields discarded by the platform. The Windows helper references the pinned pure US scan map, resolves native scans with the current static layout and observes keyboard device nodes to distinguish HID from SendInput. Equivalent output scans share ownership; different native-layout scans and Windows Enter/keypad remain separate. Canonicalize HID modifier and Pause aliases without modifying the dependency or its driver/license boundary.

Retain only idle, neutralized controller device sets by paired identity. Move their exclusive ownership to a fresh connection; never reuse another live connection's set. Rebind feedback with a fresh generation. The control consumer takes one checked nonblocking pop per iteration, so concurrent revocation can drain the mailbox without stranding the consumer. Capture the controller grant generation before dequeue and validate it under the input gate through the short local send; a popped event cannot cross revoke/regrant or be sent after revocation acknowledges. No input gate is held while awaiting cleanup. ViGEm callbacks capture their binding generation on arrival, carry only an opaque target ID and reject queued work after rebind/removal. No registry lock is held across native target removal.

Administration distinguishes an explicit rejected save from a transport or JSON failure whose outcome is unknown. Await a checked authoritative device readback after updates and individual unpairing. A lost response may still have committed; only explicit rejection supports the unchanged-authorization message. A failed readback reports uncertainty and retains the visible state without claiming that a save failed.

Both credential and pairing writers use one serialized JSON transaction preserving unrelated fields and custom separate paths. On Windows, open the original with `GENERIC_READ | DELETE` and read/delete sharing, excluding ordinary data writers through its original object and hard-link aliases, and parse the bytes captured through that guard. Capture its identity, owner/group/defaulted/control/ordered-DACL policy and separate mandatory-label, resource-attribute and central-policy selectors. The selectors require `READ_CONTROL`, not audit privilege. Refuse a nonempty central access policy because its restoration requires additional privilege. Preserve representable label/resource policy while the temporary remains empty and verify every supported authority field exactly before any payload. A separate setter-input descriptor requests the already captured automatic-inheritance model; the immutable snapshot remains the strict readback reference.

The Windows path supports local NTFS regular files with hard-link support. Preserve existing-file creation time and ordinary archive/hidden/system/not-indexed/temporary attributes; refuse read-only destinations. For a first save into genuine absence, Windows may substitute a removed name's cached creation time during rename. Only that final first-save comparison permits creation-time inequality; all identity, bytes, attributes and authority comparisons remain exact. Temporary preparation, existing-file publication, backups and recovery always compare creation time exactly. Inspect the original and temporary with a non-audit backup-stream inventory. Refuse ADS, EAs, EFS, compression, sparse/reparse files, object IDs and unknown exceptional metadata before payload. File IDs, hard-link topology and generated DOS short aliases may change across replacement; normal long filenames remain supported without inspecting or changing volume short-name policy. Last-write/change times describe the new contents.

Create a unique same-directory hard-link backup and verify that its identity, bytes and complete supported authority match the guarded original. The backup shares the original file object and is not an independent byte snapshot. Before temporary preparation or payload, open a second read/delete guard by the backup pathname while retaining the first guard. Compare both held views and both pathnames against the immutable original. Transfer function-lifetime ownership to the verified backup guard before the single checked close of the destination-open guard, then repeat the held and pathname checks after callbacks. Keep real close failures distinct from injected failures. The backup-open guard remains held through commit and recovery; no fresh observation replaces the immutable authority reference. Failure at this boundary cannot proceed to temporary preparation.

Create a protected empty temporary, restore its exact supported policy and basic metadata, write the serialized candidate, flush and check close. Reopen the temporary with read/delete access and read/delete sharing, verify the opened source against the prepared identity, bytes and supported metadata, and recheck the known destination after callbacks. Rename that source handle with `SetFileInformationByHandle(FileRenameInfoEx)`, requesting only `REPLACE_IF_EXISTS | POSIX_SEMANTICS` for a known replacement and zero flags for genuine absence. The POSIX flag permits retaining the original-object guard and compatible delete-sharing readers; a reader denying delete sharing refuses the initial guard before effects. Use the same source-handle-bound operation for a verified backup restore. Checked-close each rename handle immediately after the syscall and before final verification or recovery callbacks, retaining syscall and close failures separately. Unsupported extended rename fails explicitly. Never remove the original first, enable cross-volume copying or fall back to older Move/Replace operations. `ReplaceFileW` can merge inherited ACEs into explicit grants. Verify the committed destination against the prepared temporary, including exact controls and ordered ACEs; there is no final auto-inheritance exception or post-payload access-policy repair.

Return failed-but-unchanged only when the original remains known, or failed-but-restored after replacing a known candidate with a verified old backup and checking the result. Never restore over an unrelated external replacement. Uncertain recovery retains secured material, blocks further updates in the current process and reports operator recovery; prior in-memory authorization remains published on failure. A verified commit whose backup cleanup fails is successful persistence with a bounded cleanup diagnostic and retained material. Precommit cleanup failures are also diagnosed. POSIX behavior remains unchanged: preserve mode/uid/gid and refuse unsupported original or inherited access ACLs before payload or replacement.

The Windows restoration setter receives a separate descriptor whose `SE_DACL_AUTO_INHERIT_REQ` input is set exactly when the captured original has `SE_DACL_AUTO_INHERITED`. The request instructs the provider to retain its automatic-inheritance model; it is separate from the immutable descriptor used for strict readback. Synthetic repeated-save diagnostics on the exercised Windows configuration showed that omitting this input loses the stored marker after the first replacement, while supplying it preserves the exact empty-file policy through repeated saves and later parent revocation. This is bounded evidence for the setter sequence, not a guarantee for every Windows filesystem or policy. A mismatched readback still refuses the save before bytes.

## Alternatives and consequences

A second session framework or worker would duplicate existing ordering and lifetime rules. Dropping only the pending event cannot revoke an accepted socket's shared token. Clearing global keyboard/mouse state or retaining a whole input connection would break isolation. Rebinding only a feedback queue at execution time would deliver an old target event to its new owner.

Atomic replacement changes the inode. Mode copying alone cannot preserve POSIX named ACLs and can broaden file-group access. This bounded implementation refuses such saves rather than silently changing access; administrators receive a failed update and the prior authorization remains published. It does not introduce a general ACL/xattr copying framework. On Windows an unrecoverable native restore failure requires operator recovery; returning failure does not assert the old pathname is intact in that case. The retained guard excludes ordinary data writers to the old object and its backup aliases. Rename-source handles are closed before final verification; writer exclusion on the newly published pathname is not claimed. The guard does not exclude pre-existing writable mappings, ACL/EA changes or arbitrary external pathname races. Identity/byte/policy rechecks detect bounded interference; they are not a compare-and-swap guarantee. Recovery blocking is process-local and does not establish crash/restart recovery. An observer may see a candidate later rolled back after failed verification. The rename sequence has no universal crash-atomicity or power-loss durability claim.

Full audit-SACL preservation is outside this writer contract, as it was outside the previous getter/restorer contract. The implementation does not infer audit-ACE absence from a non-audit inventory and does not request or enable unconditional audit privilege. Exact arbitrary audit-policy preservation requires a separate privileged design. This limitation does not waive the separately readable mandatory label, resource attributes or central policy.

## Validation

The [P1b work item](../work-items/P1b-device-permissions.md) distinguishes prepared regressions from execution. Required evidence includes real HTTPS route denial, persistence failure and interleaved credential updates, accepted-token and shutdown barriers, queued/delayed input after revoke/regrant, simultaneous held contributions, fresh reconnect state and stable retained controller IDs. Native compilation, platform execution, independent review, real clients and physical display/driver qualification remain separate requirements.

## Supersession

Extends ADR-001's dispatch-time snapshot with session/input reconciliation; its connection identity remains unchanged.
