# ADR-002: serialize device authority with session and input effects

- Status: proposed; implemented candidate awaiting independent review and execution
- Date: 2026-10-23
- Relevant requirement IDs: A01-A04, DEC-21, DEC-22, DEC-44, DEC-45; T07/T08/T17

## Context

[ADR-001](001-connection-bound-identity.md) binds HTTPS requests to their original pairing, but a dispatch snapshot cannot revoke a launch already retained by an RTSP socket or input already queued for a worker. The existing host has one RTSP owner and one input worker. Retaining a whole input connection across reconnects also retains its queue and held state, which lets old cleanup affect its successor.

Credentials and paired devices normally share one JSON file. Independent read/modify/write operations can lose a successful password or permission update. A replacement file must be secured before writing credentials or certificates and preserve the original file's access restrictions.

## Decision

Persist an explicit validated permission mask separately from the enabled gate. Every new pairing, including the first device, starts at zero. Missing or invalid stored masks mean zero. Preserve the pinned Apollo permission values and its List/View/Launch inclusion hierarchy; advertise only the implemented five input categories and three application actions. The authenticated, CSRF-protected administration endpoint updates either field without supplying a default for an omitted field.

Serialize durable pairing mutations through publication and reconciliation. Save the candidate before publishing it; retain prior in-memory authority on failure. Release the authorization mutex before awaiting session or input cleanup. Reconcile on the existing RTSP `io_context`, where launch preparation reserves the single pending slot before effects. A shared launch token carries its original pairing revision, readiness, cancellation and one-admission state. Recheck it at socket dispatch and immediately before ANNOUNCE allocation. Control-thread reservation cleanup posts without waiting, because RTSP cleanup may join that thread. Publish the shutdown fence before scheduling owner cleanup so a racing operation completes or rejects instead of waiting on an abandoned future.

Effective View permits joining the selected application. A different application while consumers remain is busy. A join does not execute the application or configure its active display. Launch permits an explicit Stop for everyone, as required by DEC-45. Individual revocation or disconnect preserves other principals and does not terminate the application solely because the departing client originated it.

Each connection receives fresh input state and explicit current grants. Validate and classify packets before admission, stamp independent category generations, and check them again at dispatch. Batching stops at a category or generation boundary so intervening modifier packets retain their order. Close revoked gates, advance their generations and await isolated cleanup on the existing worker before acknowledging the mutation. Delayed repeat, mouse, controller-back and initial mouse movement carry the same generation checks. Record each connection's actual mapped key and mouse contributions; first-owner press and last-owner release preserve another connection's held input, including synthetic modifiers and all five mouse buttons. Contribution identity ignores fields discarded by the platform. The Windows helper references the pinned pure US scan map, resolves native scans with the current static layout and observes keyboard device nodes to distinguish HID from SendInput. Equivalent output scans share ownership; different native-layout scans and Windows Enter/keypad remain separate. Canonicalize HID modifier and Pause aliases without modifying the dependency or its driver/license boundary.

Retain only idle, neutralized controller device sets by paired identity. Move their exclusive ownership to a fresh connection; never reuse another live connection's set. Rebind feedback with a fresh generation. The control consumer takes one checked nonblocking pop per iteration, so concurrent revocation can drain the mailbox without stranding the consumer. Capture the controller grant generation before dequeue and validate it under the input gate through the short local send; a popped event cannot cross revoke/regrant or be sent after revocation acknowledges. No input gate is held while awaiting cleanup. ViGEm callbacks capture their binding generation on arrival, carry only an opaque target ID and reject queued work after rebind/removal. No registry lock is held across native target removal.

Administration distinguishes an explicit rejected save from a transport or JSON failure whose outcome is unknown. Await a checked authoritative device readback after updates and individual unpairing. A lost response may still have committed; only explicit rejection supports the unchanged-authorization message. A failed readback reports uncertainty and retains the visible state without claiming that a save failed.

Both credential and pairing writers use one serialized JSON transaction preserving unrelated fields and custom separate paths. Secure a unique sibling before writing. Windows captures the actual owner/group/DACL with `GetNamedSecurityInfoW`, retaining an immutable original and a separate protected creation descriptor. Restore the original protected or unprotected policy explicitly while the temporary remains empty, then verify ownership, ordered ACE bytes, DACL presence and every descriptor control before writing. Refuse EFS files before creating a plaintext temporary. Use `ReplaceFileW` with a backup to retain the destination's metadata. Its final auto-inheritance marker may change from zero to one only when every other control, ownership field and ordered ACE remains identical; inherited rights must still respond to later parent revocation. Documented partial replacement failures restore the old backup; a failed restoration retains secured recovery material, reports failure and blocks further writes until operator recovery. POSIX preserves mode/uid/gid. Linux, macOS and FreeBSD detect access ACLs using their native interfaces; an extended ACL that this transaction cannot preserve causes refusal before bytes or replacement. This also checks ACLs inherited by the temporary.

## Alternatives and consequences

A second session framework or worker would duplicate existing ordering and lifetime rules. Dropping only the pending event cannot revoke an accepted socket's shared token. Clearing global keyboard/mouse state or retaining a whole input connection would break isolation. Rebinding only a feedback queue at execution time would deliver an old target event to its new owner.

Atomic replacement changes the inode. Mode copying alone cannot preserve POSIX named ACLs and can broaden file-group access. This bounded implementation refuses such saves rather than silently changing access; administrators receive a failed update and the prior authorization remains published. It does not introduce a general ACL/xattr copying framework. On Windows an unrecoverable native restore failure requires operator recovery; returning failure does not assert the old pathname is intact in that case.

Primary platform references: [Microsoft ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew), [GetNamedSecurityInfoW](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-getnamedsecurityinfow), [security descriptor controls](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-descriptor-control), [MapVirtualKeyW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-mapvirtualkeyw), [Apple ACL retrieval](https://github.com/apple-oss-distributions/Libc/blob/main/posix1e/acl_file.c), [Apple ACL entry semantics](https://github.com/apple-oss-distributions/Libc/blob/main/posix1e/acl_entry.c), [FreeBSD ACL retrieval](https://man.freebsd.org/cgi/man.cgi?manpath=FreeBSD+14.3-RELEASE&query=acl_get&sektion=3) and [FreeBSD trivial ACL semantics](https://github.com/freebsd/freebsd-src/blob/releng/14.3/lib/libc/posix1e/acl_is_trivial_np.3). Actual native-scan emission retains legacy mapping mode; direct-VK identity uses the extended mapping mode to preserve implicit E0/E1 semantics. The actual pinned dependency implementations remain the compatibility source for packet formats and callback behavior.

Stable application UUIDs, display-backend ownership, clipboard, server commands, file transfer, QR pairing, migration and standalone Input Only remain later work. No rights for those operations are accepted or advertised.

## Validation

The [P1b work item](../work-items/P1b-device-permissions.md) distinguishes prepared regressions from execution. Required evidence includes real HTTPS route denial, persistence failure and interleaved credential updates, accepted-token and shutdown barriers, queued/delayed input after revoke/regrant, simultaneous held contributions, fresh reconnect state and stable retained controller IDs. Native compilation, platform execution, independent review, real clients and physical display/driver qualification remain separate requirements.

## Supersession

Extends ADR-001's dispatch-time snapshot with session/input reconciliation; its connection identity remains unchanged.
