# ADR-003: stable application identities and catalog transactions

- Status: accepted; integrated source review and local native/Web validation complete, hosted integration pending
- Date: 2026-10-25
- Relevant requirement IDs: DEC-24, DEC-26, DEC-33, DEC-44, DEC-45; identity portions of L01, D07 and T19/T20/T25

## Context

Name/artwork hashes and positional edit targets change when an application is edited. Cached clients and future shortcuts need one durable numeric ID/UUID pair. Catalog edits must preserve typed foreign settings, a running application's copied context, native file authority and the permission/admission foundation.

## Decision

Persist lowercase, nonnil, nonreserved application `uuid` and decimal-string `id` in `1..2147483647`. Retain the existing `apps` array and all other typed values. The version-one `miranda-app-identity.allocated-ids` object records numeric ID to UUID allocations, including retired entries. Both directions must be unique. A ledger entry is never a launch target. Missing identities are committed before publication; invalid or conflicting identities preserve the source and reject the update. Every explicit identity and unambiguous legacy target is reserved before bounded fallback probing. Legacy CRC magnitude uses defined unsigned arithmetic, excluding zero and INT32_MIN.

Use insertion-preserving nlohmann ordered_json so configured environment assignments retain their stored evaluation order through normalization, editing and restart. Evaluate both legacy candidates and runtime settings on explicit owned Boost.Process environment snapshots; catalog preparation never mutates the native parent environment. Owned Windows assignment reuses the existing case-insensitive key spelling; POSIX names stay distinct and exact. Working-directory inference uses the prepared PATH. At the launch boundary, POSIX basename resolution preserves the pinned Boost prefix grammar and argument suffix and refuses a missing prepared target without native-PATH fallback. Windows retains association handling, user-environment merging and its existing temporary native PATH override/RAII restoration during execution, using working-directory precedence followed by the prepared PATH. Use public nlohmann SAX events before DOM parsing to reject duplicate keys, integer overflow before float conversion and excessive nesting. Runtime parsing can consume normalized text through property_tree; persisted app JSON never passes through its serializer. Ordinary editing cannot replace identities. Supported fields merge into retained typed records; unknown nested preparation-command members are retained through unambiguous command matching, or an ambiguous lossy edit is rejected. Explicit empty command lists clear those supported lists.

Catalog operations execute on the existing RTSP owner, using its startup/offline fallback. Catalog lock order is owner then process state then state-file. Acquire the process guard before the transaction and retain it through nonthrowing publication. Direct process launch/liveness/cleanup consumers use the same recursive guard and keep it for the entire referenced-environment consumer, so publication cannot replace/free that environment during real exited-process cleanup. Value accessors return owned snapshots; legacy reference accessors exist only for quiescent test fixtures. The guard retains shared mutex storage across quiescent proc_t moves, unlocking before storage destruction. Permission mutation keeps mutation then authorization then state-file, releasing authorization/state locks before owner reconciliation. State-file callbacks never acquire authorization, await the owner or recursively enter persistence. No process guard spans owner dispatch or an owner-to-stream-worker join. Input cleanup waits only for its existing input worker, which does not call process/RTSP operations; display revert uses its existing manager. Process liveness calls from stream control workers remain direct; redirecting them to an owner that joins those workers would deadlock shutdown.

The secured byte transaction reads exact bytes, checks an expected content revision, normalizes/mutates the DOM, and prebuilds runtime/environment/response storage before checked atomic replacement. The permission/credentials property_tree adapter uses the same native core and mutex. Preserve Windows owner/group/ordered ACEs/control, protected creation, exact empty-temporary policy verification, early EFS refusal and partial-replacement recovery/blocking; preserve POSIX mode/owner/group and unsupported-ACL refusal. Publication uses environment-pointer/vector/string swaps and never modifies the copied active `_app`, process handles or cleanup iterators. Revision caching uses canonical configured path plus exact committed bytes, without mtime suppression or advancement on failure.

Authenticated editor GET returns a response-only revision. POST/DELETE require `If-Match`; missing and stale preconditions return 428 and 409. Edits/deletion target UUID, and save retains alphabetical ordering. The UI keys rows by UUID and retains forms after explicit failures. Positional covers remain read-only.

Protocol listing emits UUID, ID and positional IDX together. Current numeric/UUID identity comes from the copied active context under the same View visibility gate. Positive numeric and nonempty UUID selectors must agree. Exactly `appid=-1` with a valid nonempty UUID is Artemis selector syntax at launch and resume; resolve it once inside authorized serialized preparation and substitute the server's positive ID. Empty UUID is absent for a valid numeric request. Other negatives, zero/UUID conflicts, duplicate query values and unknown targets fail. UUID-only launch and selector-free resume are supported. Supplied resume selectors must match the active pair. A removed active target remains joinable with authority until stopped. A join to an existing media source does not execute edited commands, configure a display or probe encoders. A running application with zero media sessions still uses the existing fresh-source display/encoder setup; application liveness is not evidence of retained capture/display lifetime. Paired UUID/certificate/revision remain the authority; application UUID adds no rights.

## Alternatives and consequences

Hashing UUIDs without an allocation ledger cannot establish deterministic non-reuse after collisions. A high-water counter handles sparse legacy IDs poorly. Reusing the typed DOM avoids lossy property_tree round trips. Retaining the current process manager and RTSP owner avoids introducing another lifetime or scheduler subsystem. The ledger adds small permanent identity metadata without retaining deleted commands. Serializing catalog publication with cleanup can delay an edit until an undo command finishes; it avoids adding another active-process lifetime subsystem and prevents duplicate cleanup from concurrent liveness checks.

External tools must preserve the authoritative ledger and serialize or atomically replace files. The native core detects external changes observed before its final write, but cannot promise compare-and-swap against arbitrary noncooperating editors. Removing the ledger externally removes its historical protection. Semantic typed preservation does not preserve whitespace. Environment assignment order is an explicit exception to generic object-key-order indifference and is retained. Unix file fsync does not establish directory-entry durability, and this work makes no power-loss guarantee beyond the native primitive.

## Validation

See [P1c work item](../work-items/P1c-stable-application-identities.md). Executed regressions cover normalization, collisions/exhaustion, typed preservation, stale editor requests, native write failures, owner dispatch and authenticated HTTPS selector admission. Locked formatting, independent integrated source review, the native build, 376 focused native tests and 230 Web tests passed; the focused suite retains one inherited licensed-driver skip. The full local suite retains the two baseline external-download failures. Final ancestry, hosted validation and current Artemis/Moonlight runtime acceptance remain pending. No monitor/shortcut functionality or whole T19/T20/T25 completion is claimed.

Public SAX behavior is documented in [nlohmann 3.11.3](https://github.com/nlohmann/json/blob/v3.11.3/README.md#sax-interface); the local 3.12.0 interface was also inspected. The bounded -1 rule follows [pinned Artemis launcher construction](https://github.com/ClassicOldSong/moonlight-android/blob/c5cf27f4dc822db0e863c4691e7a70c74bea977a/app/src/main/java/com/limelight/ShortcutTrampoline.java#L433-L445) and [wire serialization](https://github.com/ClassicOldSong/moonlight-android/blob/c5cf27f4dc822db0e863c4691e7a70c74bea977a/app/src/main/java/com/limelight/nvstream/http/NvHTTP.java#L878-L880), rather than observed current-client interoperability.
